# 踩坑日记：一个商科生的自救记录

我是商科生，这个项目是我带着几个 AI 助手（对，AI 陪我做 AI 产品）一点一点摸出来的。以下每个坑都是真踩过的，按时间顺序写。如果你也想做类似的东西，这些能让你少熬三个通宵。

## 坑 1：租了 5090 却开不了工

**现象**：按教程租了 GPU 云服务器，一跑训练就报 `no kernel image is available`。

**我以为是**：显卡故障

**真相**：5090 是新架构（Blackwell），要 CUDA 12.8 以上的环境，而教程默认镜像是 12.4。软件不认识新硬件。

**解决**：租机器时镜像必须选 CUDA 12.8+。就这一行选择，卡了我两个小时。

**一句话**：报错别慌，复制报错信息问 AI，比瞎猜快一百倍。

## 坑 2：装环境装到怀疑人生

**现象**：跑官方的安装命令，永远卡在编译一个叫 ujson 的包，半小时不动。

**我以为是**：网速慢。

**真相**：那个包的旧版本在 Python 3.12 上没有现成的安装包，pip 在尝试现场编译，而编译环境缺东缺西。

**解决**：放弃官方的全量安装命令，改成只装几个必需的包 + 指定国内镜像源。

**一句话**：官方文档的"标准流程"经常是给人添堵的，卡住了就绕路。

## 坑 3：同一个模型，两个仓库

**现象**：下基座模型，同一个网站两个名字像的仓库，一个 500 报错一个 404。

**真相**：一个是 PyTorch 原生权重（训练用），一个是 transformers 格式（推理用）。名字只差几个字母。

**解决**：两个都下，各归各位。

**一句话**：下载地址这种东西，让 AI 给你写好完整命令直接复制，别手打。

## 坑 4：给模型"减肥"，减成了傻子

**现象**：300MB 的模型有点大，我给它做了 INT8 量化，体积降到 65MB——但回答全是乱码，答案和问题对不上。

**我以为是**：量化工具用错了。

**真相**：64M 参数实在太小，动态量化砍掉的那点精度对它来说是致命的。大模型量化没事，小模型量化直接变智障。

**解决**：放弃量化，老老实实用了 287MB 的 FP32 版本。U 盘 64GB，不差这 200MB。

**一句话**：优化之前先想清楚"代价是什么"，体积换智商，不值。

## 坑 5：小模型被"话痨"系统撑爆了

**现象**：离线助手直接测试都正常，一接到 OpenClaw 里就报 `Context overflow: prompt too large`。

**我以为是**：模型上下文太小，得换个更大的模型。

**真相**：OpenClaw 给每个模型都发约 9000 token 的系统提示词（相当于进门前先塞给它一本说明书），而我给模型登记的"接待能力"太小，门都不让进。关键是——**我们的服务只用用户最后一句提问，那本"说明书"根本不用读**。

**解决**：把登记的接待能力调到 131072。登记数字变大，门就开了，实际模型负担一点没变。

**一句话**：数字是给人看的规矩，不是给模型定的极限——先搞懂规矩是谁定的。

## 坑 6：一个看不见的"流式"协议

**现象**：接入后 OpenClaw 一直转圈，最后超时。

**真相**：OpenClaw 发请求时会带一句"请用流式（SSE）回复"，我们的小服务听不懂，回了普通格式，OpenClaw 就一直等"下一段"。

**解决**：给服务加上了流式回复能力（其实我们的模型是一次性生成完的，只要"假装"流式：分段发出去再发个结束标记）。

**一句话**：接口对接，协议先行。两边说好"怎么说话"，比"说什么"更重要。

## 坑 7：U 盘变脸（盘符）

**现象**：在自己电脑上调好一切，插到别人电脑，全废——配置里写死了 `E:\`，别人的电脑 U 盘是 `F:\`。

**解决**：双保险。①启动脚本每次启动先检查盘符，变了就自动改配置；②离线助手启动时从自己所在位置推出盘符，不看配置文件。

**一句话**：凡是"会变的东西"（盘符、路径、账号），都别写死，让程序每次自己看。

## 坑 8：假故障——其实是测试工具在捣乱

**现象**：回归测试时模型突然全部答非所问，吓得我以为模型文件坏了。

**真相**：我用的命令行工具发中文会乱码，模型收到的是乱码问题，当然答非所问。

**解决**：换用 Python 发测试请求。

**一句话**：先怀疑测试工具，再怀疑产品。这不是玩笑，真能省一晚上。

## 坑 9：断网能自动接管，恢复却不会自动切回

**现象**：断网后系统自动切到小模型（爽！），网络恢复后它却赖着不走。

**真相**：OpenClaw 的"兜底"机制设计就是"顶班不交还"——主模型好了它也不知道。

**解决（现状）**：手动 `/model` 切回。够用，但不优雅。

**下一步**：做一个"状态机"——程序自己探测网络，好了就自动切回、顺便释放小模型占的内存。这个坑还没填完，欢迎来一起填。

—— sparebrain（一个正在补技术课的商科生）
